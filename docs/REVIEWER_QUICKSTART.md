# Reviewer quick start — Signet

**Purpose:** Review deterministic operational truth, event-driven state and strictly bounded AI narration.

## Reproduce documented checks

From the repository root, using the prerequisites in the [README](../README.md):

```bash
npm ci
npm test
npm run build
```

For local development, consult the environment and Supabase setup instructions before running `npm run dev`.

## Inspect first

- Append-only event kernel, projections and hash-linked evidence.
- Tenant/organization identity derived from authenticated context, not arbitrary caller input.
- Idempotent commercial commands, change-order approval and concurrency handling.
- Read-only demo workspace isolation and corresponding database controls.
- AI narration constrained to approved evidence rather than writing operational facts.

## What not to conclude

A hash chain is **tamper-evident**, not universally tamper-proof. A production-style hosted application does not by itself demonstrate external penetration testing, compliance certification, or every recovery path under real network partitions. Verify actual CI and migration/deployment status at the inspected commit.

## Suggested reviewer questions

1. Can two conflicting commercial decisions both commit?
2. How does the application reject requests across organization boundaries?
3. Can demo credentials produce operational writes?
4. Can AI-generated explanations modify deterministic state?
